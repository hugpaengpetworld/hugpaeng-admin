# คู่มือติดตั้ง

## 1. เตรียม Google Sheet

ใช้ไฟล์ `output/BMP-Booking-System-Template.xlsx` หรือ Google Sheet ที่สร้างไว้
แม่แบบมี 13 แท็บ รวม `นัดทำหมัน` และข้อมูลห้อง `CAT01–CAT11` / `DOG01–DOG07` แล้ว

อย่าเปลี่ยนชื่อแท็บหรือหัวคอลัมน์ เพราะโค้ดอ้างอิงชื่อเหล่านี้โดยตรง

## 2. สร้างโครงการ Apps Script แบบผูกกับชีต

1. เปิด Google Sheet
2. เลือก **ส่วนขยาย → Apps Script**
3. ใน Apps Script สร้างไฟล์ Script และ HTML ตามรายชื่อในโฟลเดอร์ `src`
4. คัดลอกเนื้อหาของแต่ละไฟล์ไปยังไฟล์ชื่อเดียวกัน
5. เปิด **Project Settings** แล้วเปิดการแสดงไฟล์ manifest
6. แทนที่ manifest ด้วย `src/appsscript.json`
7. ตรวจว่าเขตเวลาโครงการคือ `Asia/Bangkok`

หมายเหตุ: ไฟล์ `.gs` จะอยู่ในโครงการเดียวกันและเรียกฟังก์ชันข้ามไฟล์ได้

### อัปเกรดระบบเดิมเป็น v1.5

1. สำรอง Google Sheet และโครงการ Apps Script ก่อน
2. วางทับไฟล์เดิมด้วยไฟล์ทั้งหมดในโฟลเดอร์ `src`
3. บันทึก แล้วเลือกฟังก์ชัน `upgradeSystemV1_5`
4. กด Run หนึ่งครั้ง รอข้อความว่าอัปเกรดสำเร็จ
5. ไปที่ Deploy → Manage deployments → Edit
6. เลือก New version แล้วกด Deploy

ฟังก์ชันนี้จะเพิ่มเฉพาะหัวคอลัมน์ที่ขาด โดยไม่ลบรายการจอง ผู้ใช้ หรือข้อมูลเดิม จากนั้นให้อัปเกรดรหัสห้องตามหัวข้อเวอร์ชัน 1.7 ด้านล่าง

### อัปเกรดระบบเดิมเป็น v1.7

1. ทำสำเนา Google Sheet และสำรองโครงการ Apps Script ก่อน
2. วางทับไฟล์เดิมด้วยไฟล์ทั้งหมดในโฟลเดอร์ `src` และเพิ่ม `11_UpgradeV1_7.gs`
3. บันทึก แล้วเลือกฟังก์ชัน `upgradeSystemV1_7`
4. กด Run หนึ่งครั้ง และรอข้อความ `อัปเกรดเป็น v1.7 สำเร็จ`
5. ตรวจแท็บ `ห้องและกรง` ว่ารหัสเป็น `CAT01–CAT11` และ `DOG01–DOG07`
6. ตรวจรายการสถานะ `CHECKED_IN` ว่า `current_booking_id` ของห้องตรงกับรายการที่กำลังเข้าพัก
7. ไปที่ Deploy → Manage deployments → Edit → New version แล้วกด Deploy

ฟังก์ชันนี้ทำงานซ้ำได้โดยไม่สร้างห้องซ้ำ เปลี่ยนเฉพาะ `room_id`, `room_name`,
`assigned_room_id` และซ่อม `current_booking_id` ที่เกี่ยวข้อง รหัสการจองเดิมไม่ถูกเปลี่ยน
และไม่มีการเพิ่มหรือลำดับหัวคอลัมน์ใหม่

### ใช้ v1.5 เดิมร่วมกับเว็บไซต์ Cloudflare (v1.6)

หาก v1.5 ใช้งานอยู่แล้วและต้องการเปิดผ่าน `bmpbooking.hug-paeng.com`
ไม่ต้องรัน `setupSystem()` หรือ `upgradeSystemV1_5()` ซ้ำ ให้ทำตาม
[`INSTALL-CLOUDFLARE.md`](INSTALL-CLOUDFLARE.md) เพื่อเพิ่ม API แบบใช้กุญแจลับ
และนำหน้าเว็บขึ้น Cloudflare โดยข้อมูลเดิมใน Google Sheets จะไม่ถูกลบหรือเปลี่ยนหัวคอลัมน์

## 3. ติดตั้งโครงสร้าง

1. เลือกฟังก์ชัน `setupSystem`
2. กด Run
3. อนุญาตสิทธิ์ Google Sheets, Drive, external requests และ triggers
4. ระบบจะแสดงชื่อผู้ใช้ `owner` และรหัสผ่านชั่วคราว
5. บันทึกรหัสผ่านนั้นทันที เพราะระบบไม่สามารถแสดงรหัสเดิมอีกครั้ง

`setupSystem()` ทำงานแบบไม่ลบข้อมูลเดิม:

- สร้างแท็บที่ขาด
- เติมห้อง CAT01–CAT11 และ DOG01–DOG07 ที่ยังไม่มี
- เติมค่าตั้งต้น
- สร้างโฟลเดอร์ไฟล์แนบแบบ Private
- สร้าง trigger ตรวจรายการหมดเวลาทุก 5 นาที
- สร้าง trigger ดูแลระบบวันละครั้ง
- สร้างบัญชี owner เมื่อยังไม่มีผู้ใช้

### อัปเกรดระบบเดิมจาก v1.0 เป็น v1.1

1. สำรอง Google Sheet ก่อน
2. วางทับไฟล์เดิมด้วยไฟล์ v1.1 และเพิ่ม `09_SterilizationService.gs`
3. เลือกฟังก์ชัน `upgradeSystemV1_1`
4. กด Run หนึ่งครั้ง
5. ตรวจว่ามีแท็บ `นัดทำหมัน` และรายการจองเดิมมีรหัสห้องที่ระบบกำหนดให้
6. สร้าง Web app deployment version ใหม่

ฟังก์ชันอัปเกรดจะไม่ลบข้อมูลเดิม โดยเพิ่มแท็บ/ค่าตั้งต้น/รายการอ้างอิง
และกำหนดห้องให้รายการค้างคืนที่ยังไม่มีห้องเท่าที่ความจุรองรับ

## 4. Deploy Web app

1. กด **Deploy → New deployment**
2. เลือก **Web app**
3. Execute as: **Me**
4. Who has access: **Anyone**
5. กด Deploy และคัดลอก URL

เหตุผลที่ใช้ Execute as Me คือไฟล์และชีตต้องถูกอ่านเขียนภายใต้บัญชีเจ้าของระบบ
โดยลูกค้าไม่ต้องเข้าสู่ระบบ Google ตามแนวทาง Web Apps ของ Google Apps Script:
https://developers.google.com/apps-script/guides/web

URL:

- ลูกค้า: URL ที่ได้จาก Deploy
- หลังบ้าน: `URLที่ได้?page=admin`

หลังแก้โค้ด ให้สร้าง deployment version ใหม่ แล้วตรวจ URL อีกครั้ง

## 5. ตั้งค่าหลังบ้าน

1. เปิด `?page=admin`
2. เข้าด้วย `owner` และรหัสผ่านชั่วคราว
3. ระบบบังคับเปลี่ยนรหัสผ่านครั้งแรก
4. ไปที่ **ตั้งค่า**
5. กรอก:
   - ชื่อสถานบริการภาษาไทยและภาษาอังกฤษ
   - หมายเลขโทรศัพท์
   - โลโก้ JPG, PNG หรือ WEBP ไม่เกิน 1 MB
   - ธนาคาร
   - ชื่อบัญชี
   - เลขบัญชี
   - URL รูป QR PromptPay
   - LINE OA / Facebook
6. ไปที่ **ผู้ใช้งาน** เพื่อสร้างบัญชีหมอและพนักงาน

รหัสผ่านต้องยาวอย่างน้อย 10 ตัว และมีตัวใหญ่ ตัวเล็ก ตัวเลข และอักขระพิเศษ

## 6. ตั้งค่า LINE OA, Messaging API และ LIFF

ส่วนนี้ต้องทำเมื่อพร้อมเปิดจองผ่าน LINE:

1. เปิดใช้ Messaging API ให้ LINE OA ของคลินิก
2. สร้าง/ใช้ Provider และ LINE Login channel
3. เพิ่ม LIFF app โดยกำหนด Endpoint URL เป็น URL Web app
4. ตั้ง Scope ที่ต้องใช้สำหรับระบุตัวผู้ใช้
5. ออก Messaging API Channel Access Token
6. หลังบ้าน → ตั้งค่า:
   - LINE Login Channel ID
   - LIFF ID
   - Messaging API Channel Access Token
7. ใช้ LIFF URL เป็นลิงก์ “จองที่พัก” ใน LINE OA

เอกสารทางการ:

- เริ่มใช้ Messaging API: https://developers.line.biz/en/docs/messaging-api/getting-started/
- เพิ่ม LIFF app: https://developers.line.biz/en/docs/liff/registering-liff-apps/
- การส่ง Push Message: https://developers.line.biz/en/docs/messaging-api/sending-messages/

ระบบจะตรวจ ID Token กับ LINE ฝั่งเซิร์ฟเวอร์ก่อนเก็บ `line_user_id`
และไม่เชื่อค่า user ID จาก query string

## 7. ทดสอบก่อนเปิดให้ลูกค้า

ทำรายการทดสอบอย่างน้อยดังนี้:

1. จองแมว 1 ตัว 1 คืน
2. ตรวจว่าเลขห้องว่างลดลงทันที ทั้งที่สถานะยัง “รออนุมัติห้อง”
3. ปฏิเสธคำขอ และตรวจว่าห้องว่างเพิ่มกลับ
4. อนุมัติรายการเว็บไซต์ และตรวจว่าเป็น “ยืนยันการจอง” โดยไม่ต้องมัดจำ
5. อนุมัติรายการ LINE และตรวจว่ามีเวลาชำระ 1 ชั่วโมง
6. แนบสลิปและให้พนักงานตรวจรับ
7. ทดสอบรายการ LINE ที่ไม่ชำระจนหมดเวลา แล้วตรวจการคืนห้องและข้อความ LINE
8. ทดสอบน้ำหนักสุนัข 20.1 กก. และสุนัข 2 ตัวที่มีตัวใดตัวหนึ่งเกิน 8 กก.
9. ทดสอบเช็กอินและเช็กเอาต์ก่อนและหลังเวลาทำการ เพื่อยืนยันว่าระบบรองรับตลอด 24 ชั่วโมง
10. ทดสอบขอเลื่อนวันครั้งที่ 1, ครั้งที่ 2 และกรณีแจ้งน้อยกว่า 3 วัน
11. ทดสอบ OWNER, DOCTOR, STAFF ว่าเห็นและทำงานได้ตามสิทธิ์
12. ทดสอบสร้างคิวทำหมัน 4 ตัวในวันเดียวกัน และตรวจว่ารายการที่ 5 ถูกปฏิเสธ
13. เปลี่ยนคิวหนึ่งรายการเป็น “ยกเลิก” แล้วตรวจว่าสามารถรับรายการใหม่แทนได้
