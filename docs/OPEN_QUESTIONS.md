# Open Questions

คำถามในไฟล์นี้ไม่ขัดขวางการเริ่ม Phase 0–1 แต่ Codex ต้องหยุดถามก่อนลงมือในส่วนที่คำตอบมีผลต่อข้อมูลจริง ค่าใช้จ่าย หรือพฤติกรรมผู้ใช้

## ต้องตัดสินใจก่อนนำข้อมูลจริงเข้า

1. จะเริ่มฐานข้อมูลใหม่ทั้งหมด หรือนำข้อมูลจาก Google Sheets เดิมเข้ามาด้วย
   - ค่าเริ่มต้นที่ปลอดภัย: สร้างระบบใหม่และทดสอบด้วย seed data ก่อน
   - หากนำเข้า ต้องขอไฟล์ export ที่ลบข้อมูลไม่เกี่ยวข้องแล้ว และทำ dry-run พร้อมรายงานแถวที่ผิดพลาด
2. ต้องนำเข้ารายการใดบ้าง: ลูกค้า สัตว์ การจอง การชำระเงิน ผู้ใช้งาน ประวัติการใช้งาน หรือทั้งหมด
3. รหัสการจองเดิมจะเก็บเพื่ออ้างอิงนานเท่าใด

## ต้องตัดสินใจก่อนเปิดใช้งานจริง

1. บัญชีอีเมลเริ่มต้นของเจ้าของคลินิกและผู้ดูแล Platform Owner
2. ระยะเวลาเก็บเอกสารวัคซีน สลิป และข้อมูลส่วนบุคคลหลังสิ้นสุดบริการ
3. LINE OA production credentials, ข้อความแจ้งเตือน และผู้รับผิดชอบกรณีส่งข้อความล้มเหลว
4. ค่าเริ่มต้นของ Temporary Support Access เช่น 1 ชั่วโมงหรือ 4 ชั่วโมง และผู้มีสิทธิ์อนุมัติ
5. ยืนยันรูปแบบเลขใบเสร็จจริง (ข้อมูลหัวใบเสร็จตัดสินใจแล้วว่าแสดงที่อยู่/เบอร์โทรเป็นค่าเริ่มต้น และแสดงข้อมูลภาษีเฉพาะเมื่อ OWNER เปิดใช้และตั้งค่า)
6. สิทธิ์ของหมอและพนักงานในการยกเลิก คืนเงิน ปรับยอด และออกใบเสร็จใหม่

## เรื่องที่คงพฤติกรรมเดิมไว้ชั่วคราว

- รายการทำหมันใช้ `F-ชื่อ/เพศ` สำหรับแมว และ `C-ชื่อ/เพศ` สำหรับสุนัข แม้รหัสห้องเปลี่ยนเป็น `CATxx` และ `DOGxx` แล้ว จนกว่าผู้ใช้จะสั่งเปลี่ยน
- แสดงวันที่เป็น ค.ศ. รูปแบบ `DD-MM-YYYY`; เก็บข้อมูลภายในเป็น ISO/UTC
- ระบบแรกเปิดใช้กับคลินิกเดียว แต่ทุกตารางและสิทธิ์ต้องพร้อมรองรับหลาย tenant

## วิธีจัดการคำตอบ

เมื่อผู้ใช้ตอบคำถามใด ให้:

1. เพิ่มบันทึกลง `docs/DECISIONS.md` พร้อมวันที่
2. แก้เอกสารข้อกำหนดที่เกี่ยวข้อง
3. เพิ่มหรือแก้ automated tests ก่อนหรือพร้อม implementation
4. ห้ามเปลี่ยนข้อมูล production ย้อนหลังโดยไม่มี migration และแผนสำรอง
